## 项目概述

**打卡提醒 App** 是一款智能打卡辅助工具，旨在帮助用户避免忘记上下班打卡。App 通过结合**时间触发**与**地理围栏（Geofencing）** 技术，在合适的时机提醒用户完成打卡，并支持自动跳转至企业微信、飞书等第三方打卡应用。同时提供上班自动打卡、下班延迟打卡等灵活功能，适应不同的工作场景。

## 功能特性

### 核心功能一览

| 功能 | 说明 | 触发方式 | 默认状态 |
|------|------|----------|---------|
| ⏰ 上下班打卡提醒 | 在预设的时间范围内，检查定位并提醒打卡；确认后进入睡眠状态 | 时间范围 + 地理围栏 | ✅ **开启** |
| 📲 自动打卡（跳转） | 确认打卡后自动跳转至第三方打卡 App，完成后引擎进入睡眠 | 用户确认后触发 | ❌ 关闭 |
| 🚀 上班自动打卡 | 开启后实时监测位置，到达公司附近（可设置距离）时自动跳转打卡；完成后进入睡眠 | 纯地理围栏（无需时间范围） | ❌ 关闭 |
| ⏳ 下班打卡延迟 | 加班场景下推迟打卡提醒，确认打卡后进入睡眠 | 用户手动设置 | ❌ 关闭 |
| 📊 打卡记录分析与 AI 总结 | 查询历史打卡记录，以图表展示上班时长、加班情况，AI 生成工作习惯总结与建议 | 用户主动查看 | ❌ 关闭 |
| 🗺️ 地理围栏定位 | 基于 GPS/网络定位，检测用户是否在公司附近（可设置距离） | 持续后台定位 | —（基础服务） |
| 🔔 震动 + 弹窗提醒 | 模仿闹钟的强提醒方式 | 满足条件时触发 | —（基础服务） |
| 💤 睡眠/唤醒机制 | 打卡确认后停止所有提醒，下一个时间范围自动唤醒 | 时间调度 | —（基础服务） |

### 1. 上下班时间与地址设置

用户在首次使用时需要配置基本信息：

- **上班打卡时间范围**：设置一个时间段，在此范围内触发打卡提醒。例如：`09:00 ~ 11:00`
- **下班打卡时间范围**：设置一个时间段，在此范围内触发打卡提醒。例如：`17:00 ~ 19:00`
- **上班地址**：通过地图选点或手动输入公司地址，App 记录经纬度坐标
- **可设置多组打卡时间段**：适用于轮班制或多办公地点场景

#### 1.1 地理围栏半径设置

用户可自定义触发打卡提醒的距离范围：

| 项目 | 说明 |
|------|------|
| ⚙️ 默认值 | **200 米** |
| 📏 可设置范围 | 50 米 ~ 5000 米 |
| 🎚️ 设置方式 | 滑块拖动或手动输入数值 |

##### 距离值校验规则

| 用户输入值 | 系统行为 |
|-----------|----------|
| 1 米 ~ 1000 米 | ✅ 正常接受，视为有效地理围栏半径 |
| **> 1000 米** | ⚠️ **弹出警告弹窗**：*"您设置的距离为 X 米，超过 1000 米。公司通常应在较小范围内，请确认是否设置正确？"*<br>选项：`[确认设置]` / `[重新设置]` |
| < 50 米 | ⚠️ 提示距离过小可能导致定位误差无法准确触发，建议设为 50 米以上 |

> 💡 **时间范围说明**：与传统闹钟只设一个时间点不同，本 App 的时间条件是一个**区间**（如 09:00~11:00）。只要当前时间落在这个区间内，且位置条件满足，就会触发提醒。这给予了用户更灵活的通勤和打卡窗口。
>
> 所有设置保存在本地数据库中，支持随时修改。

### 2. 上下班打卡提醒

这是 App 最核心的流程，具体工作逻辑如下：

#### 2.1 触发条件

| 条件 | 说明 |
|------|------|
| ✅ 时间条件 | 当前时间落在用户预设的**打卡时间范围**内（如上班 09:00~11:00 或下班 17:00~19:00） |
| ✅ 位置条件 | 手机 GPS/网络定位显示用户在公司地址**用户设定的半径范围**内（默认为 200 米） |

当以上**两个条件同时满足**时，触发提醒。

> ⏱️ **时间范围判定逻辑**：App 持续监测当前时间，当 `开始时间 ≤ 当前时间 ≤ 结束时间` 时，认为时间条件满足。例如用户设置上班时间为 09:00~11:00，则 09:00 到 11:00 之间的任何时间点，只要位置条件也满足，就会触发提醒。
>
> 📏 **半径判定逻辑**：App 计算用户当前位置与公司地址的直线距离，当 `距离 ≤ 用户设定的地理围栏半径` 时，认为位置条件满足。

#### 2.2 提醒机制

- **震动**：持续震动（类似闹钟震动，默认持续 5 秒）
- **弹窗提醒**：全屏或高优先级弹窗，显示内容示例：
  ```
  ┌─────────────────────────┐
  │   ⏰ 上班打卡提醒        │
  │                          │
  │   已到达公司附近         │
  │   请及时打卡！           │
  │                          │
  │   [✅ 确认打卡] [❌ 拒绝] │
  └─────────────────────────┘
  ```

#### 2.3 用户操作与反馈

| 触发情况 | 系统行为 |
|----------|----------|
| **✅ 用户确认打卡** | 立即停止当前提醒 → 触发「自动打卡（第三方应用跳转）」功能 → **提醒引擎进入睡眠状态** |
| **❌ 用户拒绝打卡** | 停止当前震动/弹窗 → 进入**间隔提醒模式** |
| **⏰ 超出打卡时间范围** | **弹窗告知用户时间范围已结束** → 等待用户点击「我知道了」→ **进入睡眠状态** |

> 💤 **睡眠状态说明**：一旦用户完成本次打卡确认，提醒引擎会立即停止所有提醒活动，并进入**睡眠状态**。在睡眠状态下：
> - 不再检查位置条件
> - 不再发送震动或弹窗提醒
> - 直到**下一个预设的打卡时间范围**到来时，提醒引擎才会自动唤醒，重新开始监测时间与位置条件
>
> 例如：用户上班时间范围是 09:00~11:00，用户在 09:30 确认打卡后，引擎立即睡眠。直到下班时间范围 17:00~19:00 到来时才会重新启动。
>
> 🔑 **超时进入睡眠的特殊规则**：当超出时间范围时，App **不会自动**进入睡眠，而是先弹出确认框告知用户，等待用户**主动点击「我知道了」** 后才进入睡眠。确保用户明确知晓提醒服务已暂停。

#### 2.4 间隔提醒模式（拒绝后）

当用户拒绝打卡后，App 进入**间隔提醒模式**：

- 默认每 **5 分钟**（用户可配置）重复一次提醒
- 每次提醒重复上述震动 + 弹窗流程
- 提醒在以下任一条件满足时停止：

  **条件一：用户确认打卡**
  ```
  用户点击确认打卡 → 跳转第三方 App → 💤 进入睡眠状态
  ```

  **条件二：当前时间超出预设的打卡时间范围**
  ```
  例：上班时间范围 09:00~11:00，当前时间到达 11:00
  
  ⚠️ 此时弹出通知：
  ┌─────────────────────────────────────┐
  │   ⏰ 打卡时间范围已结束               │
  │                                      │
  │   上班打卡时间范围（09:00~11:00）     │
  │   已结束，提醒服务将进入睡眠状态。     │
  │                                      │
  │   下一个打卡时间范围：17:00~19:00     │
  │                                      │
  │         [✅ 我知道了]                 │
  └─────────────────────────────────────┘
  
  用户点击「我知道了」后 → 💤 进入睡眠状态
  ```

  > 🔑 **关键规则**：超时后 App **不会自动**进入睡眠状态，而是先弹窗告知用户，等待用户**主动确认知晓**后，再进入睡眠。如果用户不点击确认，弹窗会持续显示（或按系统通知方式保留在通知栏），确保用户不会错过这一信息。

### 4. 上班自动打卡（位置触发）

此功能允许 App 在检测到用户到达公司附近时**自动触发打卡跳转**，无需用户手动确认，也**不需要设置时间范围**——开启后即实时监测位置。

#### 4.1 功能特点

| 特点 | 说明 |
|------|------|
| ✅ 无需时间范围 | 开启功能后 App 始终监测，不受时间限制 |
| ✅ 纯位置触发 | 只要到达公司附近（≤ 用户设定的地理围栏半径）即自动打卡 |
| ✅ 自动跳转 | 无需用户确认，直接唤起第三方打卡 App |
| ✅ 完成后睡眠 | 自动打卡成功后引擎进入睡眠状态 |

#### 4.2 工作流程

```
┌───────────────────────────────────────────────────────────┐
│ 1. 用户开启「上班自动打卡」功能                              │
│                                                           │
│ 2. 🚀 功能开启后立即启动监测                                │
│    后台持续定位，计算用户与公司的距离                         │
│                                                           │
│ 3. 当距离 ≤ 用户设定的地理围栏半径（默认为 200 米）           │
│    └→ 自动跳转第三方打卡应用                                 │
│                                                           │
│ 4. 跳转完成后 → 提醒引擎进入 💤 睡眠状态                      │
│    (当天不再触发，次日 00:00 自动重新激活监测)                │
└───────────────────────────────────────────────────────────┘
```

#### 4.3 智能定位间隔（自适应距离）

由于该功能**全天候运行**，为了最大程度平衡**定位精度**和**耗电量**，App 采用**自适应距离的动态检查间隔**策略——距离越近检查越频繁，距离越远检查越稀疏。

| 用户距离公司距离 | 定位检查间隔 | 说明 |
|----------------|-------------|------|
| **极远**（> 10 km） | 每 **60 分钟** | 距离很远，最低频率，极致省电 |
| **较远**（5 km ~ 10 km） | 每 **30 分钟** | 较远距离，低频检查 |
| **中等**（1 km ~ 5 km） | 每 **15 分钟** | 中等距离，适度频率 |
| **较近**（500 m ~ 1 km） | 每 **5 分钟** | 接近目标，提高频率 |
| **附近**（≤ 用户设定的半径 R） | **立即触发** | 到达范围，触发打卡 |

**计算公式**：

```
定位间隔(分钟) = max(5, min(60, 距离(米) / 200))
```

| 实际距离 | 计算结果 | 实际间隔 |
|---------|---------|---------|
| 12,000 米（12 km） | max(5, min(60, 60)) = 60 | **60 分钟** |
| 6,000 米（6 km） | max(5, min(60, 30)) = 30 | **30 分钟** |
| 3,000 米（3 km） | max(5, min(60, 15)) = 15 | **15 分钟** |
| 1,000 米（1 km） | max(5, min(60, 5)) = 5 | **5 分钟** |
| 500 米 | max(5, min(60, 2.5)) = 5 | **5 分钟** |
| ≤ 用户设定半径 | 立即触发 | **立即** |

> 🔋 **省电策略**：由于用户可能在公司外数公里之外，App 不会高频检查定位。当用户距离公司 10 公里以上时，仅每 60 分钟检查一次；随着距离缩小，检查频率逐步提升，确保在到达时及时触发。

#### 4.4 每日激活机制

- 上班自动打卡功能一旦开启，**每天 00:00 自动重新激活监测**
- 如果用户在某次到达公司时已成功自动打卡，引擎进入睡眠状态后，**当日不再重复触发**
- 用户也可以随时**手动关闭/重新开启**该功能

#### 4.5 与「上下班打卡提醒」的区别

| 特性 | 上下班打卡提醒（第2节） | 上班自动打卡（第4节） |
|------|----------------------|---------------------|
| 是否需要时间范围 | ✅ 需要（如 09:00~11:00） | ❌ **不需要，全天监测** |
| 触发方式 | 时间范围 + 位置双重条件 | **仅位置条件** |
| 是否需要用户确认 | ✅ 需要用户点击确认 | ❌ **无需确认，自动跳转** |
| 定位检查间隔 | 仅在时间范围内才检查 | **全天候自适应间隔**（最大1小时，最小5分钟） |
| 适用场景 | 用户希望被提醒后手动操作 | 用户希望全自动化操作 |

> 💡 **提示**：两个功能可以**同时开启**，它们互不冲突。例如：
> - 上班自动打卡负责在到达时立即跳转
> - 上下班打卡提醒作为兜底保障，在预设时间范围内再次提醒

### 5. 下班打卡延迟

当用户**需要加班**，在预设的下班时间后仍然在公司范围内时，可以使用此功能。

#### 5.1 触发场景

```
预设下班时间范围：17:00 ~ 19:00
实际场景：用户还在公司加班（当前时间 18:30，仍处于时间范围内）

App 行为：
当前时间落入下班时间范围内，且位置在公司附近
     ↓ 触发下班打卡提醒
     ↓ 用户选择「延迟打卡」
     ↓ 弹出设置界面
```

#### 5.2 延迟设置界面

```
┌──────────────────────────────────┐
│  ⏳ 下班打卡延迟                   │
│                                  │

│  ┌────────────────────────────┐  │
│  │ ○ 15分钟    ○ 30分钟       │  │

│                                  │

└──────────────────────────────────┘
```

#### 5.3 延迟期间的行为

- App 停止当前的打卡提醒
- 按照用户选择的间隔时间，定时再次提醒
- **每次提醒仍然包含震动 + 弹窗**
- 用户每次被提醒时都可以再次选择「延迟」或「确认打卡」
- **一旦用户确认打卡** → 跳转第三方 App → **提醒引擎进入 💤 睡眠状态**（直到下一个打卡时间范围）

#### 5.4 离开公司范围的自动提醒

当用户**离开公司范围**（距离 > 用户设定的地理围栏半径，默认 200 米）时，无论是否处于延迟状态，App 都会立即发送弹窗提醒。

```

│                                           │
│   您是否已完成打卡？                       │
│                                           │
│   [🔙 忘记打卡了]  [⏰ 暂不打卡]          │
└──────────────────────────────────────────┘
```

##### 用户选项及系统行为

| 用户操作 | 系统行为 |
|----------|----------|
| **🔙 忘记打卡了** | 1. 记录此次离开事件<br>2. 弹窗提示：*"您已离开打卡范围（当前距离公司约 X 米），请记得及时打卡哦！"*<br>3. 用户点击确认后 → **直接返回到「下班延迟」状态**（保持原有的间隔提醒循环）<br>  > ⚠️ 注意：此处**不会**跳转第三方打卡 App，仅作为提醒告知用户，后续仍按照延迟间隔继续提醒。 |

##### 回到公司范围的处理

当用户处于**离开公司范围的自动提醒状态**时，如果用户**重新回到公司范围**（距离 ≤ 用户设定的地理围栏半径）：

```
用户离开公司范围（触发弹窗提醒）
     │
     ├── 用户选择「忘记打卡了」→ 直接返回到下班延迟状态（不跳转第三方 App）
     │
     ├── 用户选择「暂不打卡」→ 设置延长间隔 → 继续监测
     │
     └── 用户重新进入公司范围

     │                                      │

     系统自动从「离开范围提醒模式」切换回「下班延迟提醒模式」

```

> 🔑 **关键规则**：离开公司范围的提醒**不强制用户打卡**，提供两种灵活选择：
> - **忘记打卡了**：仅弹窗提醒用户，**不跳转第三方 App**，直接**回到延迟状态**，继续原有的间隔提醒循环
> - **暂不打卡**：按照用户选择的时间延长后再次提醒
> - **回到公司范围**：自动从"离开范围提醒模式"切换回"下班延迟提醒模式"，继续原有的延迟提醒循环

#### 6.5 AI 智能总结与建议

基于用户的打卡数据，利用 AI（本地端侧模型或云端 API）生成个性化的**工作习惯总结**与**改进建议**。

##### 6.5.1 触发方式

| 触发场景 | 说明 |
|---------|------|
| 📅 **每日总结** | 用户完成下班打卡后，可选查看今日总结 |
| 📆 **每周报告** | 每周日/周一自动生成上周工作周报 |
| 📊 **月度分析** | 每月初生成上月完整分析报告 |
| 🔍 **主动查询** | 用户在记录页面随时点击「AI 分析」按钮生成 |
| 🎯 **异常触发** | 检测到连续迟到、过度加班时主动推送提醒 |

##### 6.5.2 AI 分析内容

| 分析维度 | 具体内容 |
|---------|---------|
| ⏰ **出勤规律** | 上下班时间的稳定性、准时率、迟到/早退模式 |
| ⏱️ **工作时长** | 日均时长、周均时长、与行业平均对比 |
| 🌙 **加班分析** | 加班频率、高峰时段、持续时间趋势 |
| 📈 **效率评估** | 结合打卡时间推断工作节奏（如到岗早是否对应下班早） |
| 🔄 **异常检测** | 识别异常打卡模式（如频繁晚归、突增加班） |
| 💡 **改进建议** | 基于数据给出可操作的个人时间管理建议 |

##### 6.5.4 AI 模型选型

| 方案 | 说明 | 优缺点 |
|-----|------|--------|
| **端侧模型**（推荐） | 使用设备本地 AI 模型（如 MediaPipe、CoreML、TFLite） | ✅ 数据不出设备，隐私安全<br>✅ 无需网络，响应快<br>❌ 模型能力有限，复杂分析需精简 |
| **云端 API** | 调用大模型 API（如 OpenAI、文心一言、通义千问） | ✅ 分析能力强，报告更丰富<br>❌ 需联网<br>❌ 隐私敏感（可脱敏后上传） |
| **混合方案** | 基础统计端侧处理，深层分析/报告生成调用云端 | ✅ 兼顾隐私与能力<br>✅ 用户可控制是否开启云端分析 |

> 🔒 **隐私说明**：所有打卡数据默认存储在设备本地。AI 分析优先使用端侧模型处理；如果用户选择开启云端 AI 增强分析，App 会在上传前对数据进行脱敏处理（去除具体日期、公司名称等敏感信息），并明确告知用户数据传输范围。

## 技术选型

| 模块 | 推荐技术方案 | 说明 |
|------|-------------|------|
| **前端框架** | Flutter / React Native | 跨平台开发，一套代码适配 iOS 和 Android |

| | iOS: `CLLocationManager` + `CLCircularRegion` | CoreLocation 框架 |
| **本地存储** | SQLite (通过 sqflite / Hive) | 存储打卡记录、设置项 |
| **通知系统** | Android: `NotificationCompat` + `AlarmManager` | 系统通知与定时任务 |
| | iOS: `UNUserNotificationCenter` | 用户通知框架 |
| **状态管理** | Provider / Riverpod (Flutter) | 状态管理方案 |
| **地图服务** | 高德地图 / 百度地图 SDK | 地图选点、坐标拾取 |
| **图表可视化** | fl_chart / Syncfusion Flutter Charts / ECharts (WebView) | 柱状图、折线图、饼图、热力图等图表渲染 |
| **AI 端侧模型** | TensorFlow Lite / MediaPipe / Core ML | 设备本地 AI 推理，数据不出设备 |
| **AI 云端 API** | OpenAI API / 文心一言 / 通义千问 | 云端大模型增强分析（可选，需用户授权） |
| **数据导出** | csv / pdf (通过 printing 或 pdf 库) | 打卡记录导出为 CSV、PDF 格式 |
| **节假日 API** | 中国节假日 API（开源或第三方） | 识别法定节假日用于加班判定 |

## 安装与运行

### 环境要求

- Flutter SDK >= 3.0
- Dart SDK >= 3.0
- Android SDK (API 26+) 或 iOS 13.0+

### 运行步骤

```bash
# 1. 克隆项目
git clone https://github.com/your-username/punch-clock-app.git
cd punch-clock-app

# 2. 安装依赖
flutter pub get

# 3. 运行项目
flutter run
```

### 所需权限

| 平台 | 权限 | 用途 |
|------|------|------|
| Android | `ACCESS_FINE_LOCATION` | GPS 精确定位 |
| Android | `ACCESS_BACKGROUND_LOCATION` | 后台持续定位 |
| Android | `POST_NOTIFICATIONS` | 发送通知弹窗 |
| Android | `VIBRATE` | 震动提醒 |
| Android | `SCHEDULE_EXACT_ALARM` | 精确定时提醒 |
| iOS | `NSLocationAlwaysAndWhenInUseUsageDescription` | 前后台定位 |
| iOS | `UNUserNotificationCenter` | 本地通知 |

### 已完成的阶段详情

#### Phase 1 — 数据库 (✅) 
6 张表：`punch_records`, `work_schedules`, `company_locations`, `app_settings`, `third_app_configs`, `delay_records` + 完整 CRUD + 默认种子数据。

#### Phase 2 — 设置页面 (✅)
`SettingsProvider` 状态管理 + 5 个功能开关 + 4 个配置页面（排班/地址/第三方 App/主设置）+ 间隔频率 + 数据保留。

#### Phase 3 — 距离校验 (✅)
`GeofenceValidator`（校验规则）+ `DistanceCalculator`（Haversine）+ `GeofenceRadiusPicker`（滑块组件）+ 43 个单元测试。

#### Phase 4 — 定位服务 + 围栏 (✅)
`LocationService` 抽象接口 + `MockLocationService` + `GeofenceService`（事件流 + 多地点监控）+ `LocationProvider` + 自适应间隔省电策略 + 44 个测试。

#### Phase 5 — 打卡提醒引擎 ⭐ (✅)
`PunchReminderEngine` 核心引擎：每 intervalMinutes 固定间隔检查 → 智能时间窗口判定（beforeWork/punchIn/working/punchOut/afterWork）→ 防重复提醒 → 位置自动打卡 → 手动打卡 → 延迟记录。`NotificationService` 抽象接口 + Mock。`ReminderProvider` 状态管理。48 个测试。

**引擎工作流程**：
```
Timer(每N分钟) → _executeCheck()
  ├→ 1. 找今天适用的排班 (weekDays)
  ├→ 2. 确定时间窗口 (before/punchIn/working/punchOut/after)
  ├→ 3. 查询今日打卡记录 (DB)
  ├→ 4. 判断打卡状态 (none/punchedIn/completed)
  └→ 5. 触发动作: 提醒/自动打卡/延迟记录
```

#### Phase 6 — 完整 UI (✅)
底部导航（首页/记录/设置）+ `HomeScreen` 仪表盘（今日打卡卡片 + 监测状态 + 功能启用 + 距离详情 + 快捷入口）+ `PunchHistoryScreen`（月度统计 + 记录列表 + 月份切换）+ `PunchDetailScreen`（打卡详情 + 备注编辑）+ 可复用组件（`MonthlyStatsCard`, `RecordListItem`）+ 20 个 UI 测试。

#### Phase 7-9 — 自动打卡/位置触发/延迟 (✅)
已集成到 Phase 4/5 引擎中：第三方 App 跳转 + 位置触发自动打卡 + 下班打卡延迟记录。

#### Phase 10 — 打卡数据分析引擎 (✅)
`PunchAnalysisService`（月度汇总 + 加班分析 + 异常检测）+ `ChartDataService`（柱状图/折线图/饼图/热力图数据生成）+ 4 个图表组件（`BarChartWidget`, `LineChartWidget`, `PieChartWidget`, `ChartLegend`, `StatCard` 全部使用 **CustomPaint** 零额外依赖）+ `PunchAnalysisScreen`（统计卡片 + 图表选项卡 + 加班分析 + 异常检测 + 月份切换）+ 75 个单元测试。底部导航新增第 4 个 tab「分析」。
